# ADR-0037: Источники в админке — имя обязательно, `origin`, только website/file/table

- Статус: принято
- Дата: 2026-10-08

## Контекст
P8-03: в админке нужно добавлять источники знаний, запускать синхронизацию и смотреть статусы.
Сейчас источники объявляются только в YAML тенанта и создаются `make seed` по имени (ADR-0019).
ADR-0019 предполагал, что источники из админки будут без имени, но тогда в списке админки
их нечем подписать. При этом нельзя допустить, чтобы seed перезаписал источник из админки,
если в YAML появится то же имя.

Секреты `http_api` и `database` — ссылки на env `SOURCE_SECRET_*`, общие для всех тенантов
(ADR-0017). Если editor тенанта сможет создать такой источник, он сошлётся на секрет другого
тенанта, укажет `url` своего сервера и получит секрет в заголовке.

## Решение
1. У источника из админки имя обязательно: тот же формат, что в YAML (`^[a-z0-9][a-z0-9_-]*$`,
   ≤ 64), и общая с YAML уникальность в тенанте (частичный индекс `uq_sources_tenant_id_name`).
   Занятое имя — 422 `invalid_input` с `details: [{loc: ["name"]}]`, гонку решает индекс
   (`INSERT … ON CONFLICT DO NOTHING`).
2. Колонка `sources.origin`: `yaml` (по умолчанию, все прежние источники) или `admin`.
   `make seed` с именем источника `origin=admin` останавливается с ошибкой и не перехватывает
   его. Источники `yaml` админка не меняет: их перезапишет следующий `make seed`.
   Синхронизацию запускать можно у любых.
3. В админке создаются только `website`, `file`, `table`; `http_api` и `database` — только
   в YAML тенанта (их секреты и так требуют правки env платформы). Когда появится шифрованное
   хранилище секретов тенанта (альтернатива в ADR-0017), ограничение можно снять.
4. Конфиг — YAML, его разбирает бэкенд и проверяет модель коннектора (как у seed). Ошибки
   конфига приходят в `details` с путём `["config_yaml", …путь в конфиге]`.
5. Синхронизация из админки ставится в очередь воркера (`request_sync` → `ArqSyncQueue`).
   API держит отдельный клиент arq к тому же Redis. Время запроса синхронизации —
   `source_syncs.created_at` (`clock_timestamp()`), по нему история идёт от новой к старой.

Чтение источников и истории — роль `viewer`, создание и запуск синхронизации — `editor`.

## Альтернативы
- **Источники админки без имени, подпись — отдельной колонкой `title`.** Две разные сущности
  «ключ» и «подпись» без пользы: у источника из YAML подписи нет, у источника из админки нет
  ключа. Отклонено.
- **Имя без `origin`: seed по имени забирает любой источник.** Совпадение имени тихо
  перезаписало бы конфиг, созданный в админке. Отклонено.
- **Разрешить `http_api`/`database` с проверкой, что имя env содержит slug тенанта.**
  Конвенция `SOURCE_SECRET_<ТЕНАНТ>_…` не защищает от тенанта, чей slug — префикс чужого,
  и всё равно нужна правка env платформы. Отложено до хранилища секретов тенанта.

## Последствия
- ADR-0019 п. 2 уточнён: у источников из админки тоже есть имя, декларацию их отличает `origin`.
- Файлы `file`/`table` (P8-03b) загружаются через API в каталог источника (ADR-0012) и только
  у `origin=admin`: каталог источника из YAML зеркалирует `make seed`. Тело запроса — байты файла
  без multipart (`python-multipart` нет в зависимостях), запись атомарная (скрытый временный
  файл + rename). Лимиты: 20 МБ на файл (не больше лимита коннекторов), 200 файлов на источник.
  Квоты диска на тенант нет.
- Правка конфига и удаление источника из админки не реализованы. Для удаления нужна чистка
  Qdrant и каталога файлов.
- `SourceSync.error` и ошибки элементов показываются editor/viewer тенанта как есть. В них
  бывают серверные пути, например каталог источника.
