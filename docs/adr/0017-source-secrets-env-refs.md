# ADR-0017: Секреты источников знаний — ссылки на env `SOURCE_SECRET_*`

- Статус: принято
- Дата: 2026-10-04

## Контекст
Коннекторам `http_api` (P4-09a) и `database` (P4-09b) нужны учётные данные клиента:
API-токен, логин/пароль, DSN базы. `Source.config` хранится в Postgres открытым JSON и
показывается в админке, а правило проекта — «секреты только из env». Хранилища секретов
(vault, шифрованная таблица) в пилоте нет.

Если конфиг может сослаться на любую переменную окружения, источник с
`secret_env: OPENAI_API_KEY` и `url` на сервер тенанта отправит ключ платформы наружу:
воркер видит все секреты платформы.

## Решение
- В конфиге источника — только **имя** переменной: `auth: {type: bearer, secret_env: ...}`,
  позже `dsn_env` у `database`. Значение конфиг не содержит.
- Имя обязано соответствовать `SOURCE_SECRET_[A-Z0-9_]+`; иное имя или пустая переменная —
  ошибка синхронизации (до первого запроса). Переменные платформы под префикс не попадают.
- `SourceSecrets` (knowledge/infrastructure) получает словарь при сборке воркера:
  `source_secrets_env()` — `SOURCE_SECRET_*` из `.env` и окружения (окружение важнее;
  pydantic-settings не переносит `.env` в `os.environ`).
- `http_api`: секрет — только через `auth` (bearer, заголовок, basic); заголовки
  `Authorization`, `Cookie` и т. п. в `headers` запрещены. Редиректы и `next_url` — только
  на хост из `url`, чтобы секрет не ушёл на другой сервер. Секрет в query-параметре не
  поддерживается: URL попадает в тексты ошибок и логи.

## Альтернативы
- **Секрет прямо в `Source.config`.** Просто, но секрет в БД открытым текстом, в бэкапах и
  админке. Отклонено.
- **Шифрованная таблица секретов тенанта (ключ из env).** Правильное решение для
  самообслуживания, но нужны API/UI управления, ротация ключа. Отложено до админки; ссылка
  `secret_env` тогда заменится ссылкой на запись, формат конфига почти не изменится.
- **Любое имя env без префикса.** Утечка секретов платформы через конфиг. Отклонено.

## Последствия
- Новый источник с секретом требует правки окружения воркера (и перезапуска) — это
  операция платформы, не тенанта. Приемлемо для пилота.
- Имена переменных общие для окружения и между тенантами не изолированы; конвенция имени —
  `SOURCE_SECRET_<ТЕНАНТ>_<ИСТОЧНИК>`.
- Тот же механизм используют `database` (P4-09b) и HTTP-инструменты тенанта (§9).
