# ADR-0019: Источники тенанта объявляются в его YAML; seed — по имени, файлы копируются

- Статус: предложено
- Дата: 2026-10-04

## Контекст
P4-10 загружает данные пилота: базу знаний (MD, коннектор `file`) и каталог (CSV, `table`).
Админки источников ещё нет (P8-03), создать Source можно было только записью в БД. Коннекторы
`file`/`table` читают каталог `<KNOWLEDGE_FILES_DIR>/<tenant_id>/<source_id>/` (ADR-0012), а оба
id известны только после создания записей. Нужен воспроизводимый путь «с нуля до проиндексированных
данных» одной командой — для разработки, демо и эвалов (`make eval` теперь ходит в данные тенанта
из БД, ADR-0011 п.5).

## Решение
1. В `config/tenants/<slug>.yaml` — секция `sources`: `name` (ключ в пределах тенанта), `kind`,
   `config` (как `Source.config`), `files` (только `file`/`table`: каталог относительно YAML).
   tenants хранит секцию как есть; разбирает и проверяет её knowledge
   (`parse_source_declarations`), конфиг — моделью коннектора до первой записи в БД.
2. `sources.name` — nullable, уникально в пределах тенанта (частичный индекс). Источники без
   имени (будущие из админки) декларации не касаются. Уточнено ADR-0037: у источников из
   админки тоже есть имя, их отличает `origin=admin`, и seed их не перехватывает.
3. `make seed` после тенанта делает upsert источников по имени: новый — создать, другой
   `config` — обновить, смена `kind` — ошибка. Файлы `files` зеркалируются в каталог источника
   (изменившиеся копируются с новым mtime, лишние удаляются). Источники, которых нет в YAML,
   не удаляются — seed о них сообщает.
4. `app.cli sync` (`make sync`) синхронизирует именованные источники в своём процессе, без
   воркера и Redis; по умолчанию полная синхронизация — смену конфига `table` курсор по mtime
   не видит. `make pilot` = migrate + seed + sync.

## Альтернативы
- **Отдельный скрипт загрузки пилота с захардкоженными источниками.** Быстрее, но это бизнес-
  специфика в коде и второй путь создания источников, который разойдётся с конфигом тенанта.
- **Путь к файлам прямо в `Source.config`.** Отклонено в ADR-0012: изоляция зависела бы от
  корректности конфига.
- **Ставить синхронизацию в очередь воркера.** Для загрузки нужен запущенный воркер, а итог
  не виден в выводе команды; путь через очередь остаётся для API и админки.

## Последствия
- Данные демо-тенантов воспроизводятся из репозитория: `make up && make pilot`.
- `files` — механизм dev/демо из доверенного репозитория: путь может указывать куда угодно на
  диске. Загрузка файлов пользователями (P8-03) пойдёт через API в тот же каталог источника,
  не через YAML.
- Админка (P8) должна учитывать, что именованный источник перезапишет следующий `make seed`;
  правки таких источников — в YAML.
- Удаление источника и его каталога по-прежнему не реализовано.
