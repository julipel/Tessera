# ADR-0015: Реранкинг search_knowledge — HTTP `/rerank` в формате Cohere/Jina

- Статус: предложено
- Дата: 2026-10-04

## Контекст
`search_knowledge` (P4-07a/b) ищет гибридно (dense + BM25, RRF в Qdrant). RRF только
сливает ранги и не оценивает, отвечает ли фрагмент на вопрос. Поэтому при ничьей наверх
может выйти фрагмент, совпавший с запросом по случайному слову. В тесте качества
P4-07a запрос «Как сдать покупку обратно?» поднял «Программу лояльности» выше «Возврата».
AgentConfig уже содержит `knowledge.search_knowledge.rerank` (по умолчанию `true`), порт
`Reranker` и откат к RRF при сбое уже есть в `KnowledgeSearch`. Нет только реализации.

Ограничения:
- Новые зависимости добавляются только по явному запросу (CLAUDE.md). Локальный
  cross-encoder тянет torch или onnxruntime и модели в рантайме.
- Поиск выполняется в ходе диалога: таймаут инструмента 10 с, и в него входят эмбеддинг
  запроса, Qdrant и реранкинг.
- Провайдер должен меняться без кода: облачный API или self-hosted сервер в контуре клиента.

## Решение
1. **`HttpReranker`** (`knowledge/infrastructure/http_reranker.py`) реализует порт `Reranker`
   на httpx, без SDK. Он использует общее подмножество Cohere `/v2/rerank` и Jina
   `/v1/rerank`, которое поддерживают и self-hosted серверы (Infinity, vLLM):
   - запрос: `POST {model, query, documents: [str], top_n}`, заголовок
     `Authorization: Bearer <key>` (если ключ задан);
   - ответ: `results[].index` и `results[].relevance_score`, остальные поля игнорируются;
   - порядок восстанавливается сортировкой по `relevance_score`, на сортировку сервера не
     полагаемся; шкала score у провайдеров разная, поэтому его абсолютное значение не
     используется;
   - сеть, не-2xx и неожиданный JSON → `RerankError`.
2. **Настройка — env окружения**: `RERANK_URL` (полный адрес endpoint), `RERANK_MODEL`,
   `RERANK_API_KEY`, `RERANK_TIMEOUT_S` (по умолчанию 3 с). Реранкер собирается, только если
   заданы URL и модель. Если задано одно из двух — предупреждение в лог, реранкинг выключен.
3. **Тенант решает только, нужен ли реранкинг** (`rerank` в AgentConfig). Провайдер и модель
   общие для окружения. Если окружение реранкер не настроило, `rerank: true` не действует.
4. **Сбой реранкера не ломает поиск**: `KnowledgeSearch` отдаёт порядок RRF и пишет
   предупреждение (P4-07a). Кандидатов на реранкинг `max(3·top_k, 20)`.

## Альтернативы
- **LLM-реранкер** (listwise-промпт через OpenAI SDK в knowledge/infrastructure). Зависимостей
  не нужно, и модель понимает русский. Отказались: +1–2 с и стоимость токенов на каждый
  поиск, в knowledge появился бы второй LLM-клиент, а ответ надо разбирать из текста модели.
- **Локальный cross-encoder** (sentence-transformers / ONNX, напр. `bge-reranker-v2-m3`).
  Лучшее качество без внешнего API. Отказались: тяжёлые зависимости и ресурсы в процессе API.
  Тот же сервер можно поднять отдельно (Infinity, TEI с совместимым API) и подключить через
  `RERANK_URL` без изменений кода.
- **Только порт без реализации.** Флаг `rerank` из конфига тенанта ничего бы не делал. Задача
  P4-07 требует реранкинга, а провайдеры с этим форматом доступны уже сейчас.
- **SDK провайдера** (`cohere`). Новая зависимость и привязка к одному провайдеру. Формат
  простой и стабильный, адаптер на httpx — около 60 строк.

## Последствия
- Новых зависимостей нет. Провайдер меняется через env: Cohere, Jina, self-hosted.
- Реранкинг — внешний сетевой вызов на каждый поиск: задержка (до `RERANK_TIMEOUT_S`) и плата
  провайдеру. Учёт стоимости — вместе с observability.
- Формат TEI (`texts` вместо `documents`, ответ — массив) не поддержан. Нужен — отдельный
  адаптер за тем же портом.
- Фрагменты знаний уходят внешнему провайдеру реранкинга, как тексты уходят провайдеру
  эмбеддингов и LLM. Для тенантов с требованиями к данным — self-hosted сервер.
- Порога релевантности нет: реранкер только переупорядочивает. Отсечение по score —
  отдельное решение (шкалы у провайдеров разные).
- Согласуется с ADR-0001 (порт в domain, адаптер в infrastructure) и ADR-0014 (внешние
  сервисы — тонкие httpx-адаптеры без SDK). Ничего не заменяет.
