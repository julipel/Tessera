# ADR-0016: `query` в search_catalog — полнотекстовый поиск Postgres

- Статус: принято
- Дата: 2026-10-04

## Контекст
Контракт `search_catalog(query?, filters?, sort?, limit?)` (contracts.md §4) и ADR-0003
обещают структурные фильтры «плюс, опционально, семантический запрос по описанию».
Сейчас семантику взять не из чего: сущности в Qdrant не индексируются (architecture.md §8),
документов-описаний с `entity_id` ни один коннектор не создаёт, у `EntityItem` нет поля
описания. Модель же часто ищет словами («крем для сухой кожи», «шампунь»), а не только
фильтрами по полям, которые ещё нужно угадать.

## Решение
1. `query` ищется полнотекстово в Postgres, в том же SQL-запросе, что и фильтры.
   Документ сущности — `to_tsvector('russian', title + category)` плюс
   `jsonb_to_tsvector('russian', attributes, '["string"]')`. Ключи атрибутов и числа в поиск
   не попадают.
2. Запрос строится через `plainto_tsquery('russian', …)`. Это даёт стемминг и стоп-слова,
   а синтаксис tsquery от модели не разбирается. В запросе `&` заменяется на `|`: подходит
   любое из слов, ранг — `ts_rank`. Запрос из одних стоп-слов не фильтрует.
3. Порядок выдачи: сначала то, что в наличии, затем `sort` (`relevance` — по `ts_rank`),
   затем название и id.
4. Индекс не строится: tsvector считается на лету. При объёмах пилота (сотни и тысячи строк
   на тенанта) запрос и так дешёвый; GIN-индекс по выражению добавим, когда понадобится.
5. Доступ к каталогу — `SqlCatalog`: на каждый вызов своя короткая сессия из фабрики, а не
   сессия стрима чата. Инструменты хода не делят `AsyncSession` с записью сообщений.

## Альтернативы
- **Индексировать сущности в Qdrant** (текст сущности → точка с `entity_id`, гибридный
  поиск, затем пересечение с фильтрами из Postgres). Это настоящая семантика, но нужно
  менять пайплайн индексации, удалять точки вместе с сущностями и делать два запроса с
  пересечением. Это объём отдельной задачи; решение откладывается, пока не появятся
  описания сущностей и эвалы, показывающие, что лексического поиска не хватает.
- **ILIKE / pg_trgm.** Без стемминга «сухих» не найдёт «сухой»; pg_trgm требует расширения
  и миграции.
- **AND-семантика (`websearch_to_tsquery`).** Длинный запрос модели почти всегда даёт
  пустую выдачу.

## Последствия
- Синонимы и перефразировки не находятся («увлажняющий» ≠ «для сухой кожи»). Модели нужно
  совмещать `query` с фильтрами; это подскажет описание инструмента (P4-08b).
- Конфигурация `russian` фиксирована для всех тенантов. Английские слова стеммятся
  английским стеммером, словари других языков — при появлении таких тенантов.
- Переход на векторный поиск по сущностям не меняет порт `Catalog` и аргументы
  инструмента: меняется только реализация `query`.
