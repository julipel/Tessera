# ADR-0020: Быстрые ответы — встроенный инструмент, кнопки карточек — из конфига тенанта

- Статус: предложено
- Дата: 2026-10-04

## Контекст
P5-03: в протоколе есть SSE-событие `suggestions` (быстрые ответы под сообщением) и
`input.type=action` (нажатие кнопки компонента), но их никто не порождал: `show_entities`
собирал карточки без кнопок, а подсказки модель могла дать только текстом. По ADR-0004 UI в чат
отправляют инструменты бэкенда, а не текст модели. Кнопки и подписи — бизнес-специфика,
в ядре их быть не должно. Подпись нажатой кнопки нужна и в истории, и модели: по одному
`action_id` ни пользователь, ни модель не поймут, что выбрано.

## Решение
1. Встроенный инструмент `suggest_replies(options)` — 1–4 реплики от лица пользователя
   (≤ 40 символов, без повторов). Результат инструмента получает поле `suggestions`; цикл
   отдаёт событие `SuggestionsOffered`, chat — SSE `suggestions` с
   `input: {type: text, text: label}`. Включается тенанту через `tools.builtin`. В историю
   подсказки не сохраняются: актуальны только под последним ответом.
2. Кнопки `product_card` задаёт `knowledge.catalog.card_actions` (`action_id`, `label`,
   `style`, до 3); `show_entities` подставляет `payload: {entity_id}`.
3. `ActionInput.label` (необязательное): клиент отправляет то, что видел пользователь.
   История показывает подпись, модель получает `[Нажата кнопка «label» (action_id) {payload}]`.

## Альтернативы
- Подсказки в тексте ответа по разметке (например, блок в конце сообщения) — хрупкий парсинг
  стрима, текст уже ушёл клиенту до разбора.
- Структурированный вывод (JSON-ответ модели) — ломает стриминг текста и различается
  у провайдеров.
- Подсказки из конфига по сценарию/слоту — статичны, не покрывают свободный диалог; можно
  добавить позже поверх того же события.
- Кнопки карточек в ядре («Подробнее», «Выбрать») — бизнес-логика и язык в ядре.

## Последствия
- Подсказки — текст модели, но без данных: в описании инструмента запрет на цены, ссылки
  и названия не из данных; длина и число ограничены схемой.
- Вызов инструмента — ещё один шаг цикла (лишний вызов модели), если модель не завершит
  ответ в том же шаге. Описание просит вызывать вместе с текстом и после вызова не
  дописывать; качество поведения — через эвалы (P6-03).
- Подсказки после перезагрузки страницы не восстанавливаются (при необходимости — P5-07,
  поле в истории сообщения).
- Нажатие action не проверяется на сервере против показанных кнопок: это ввод пользователя,
  модель трактует его как данные.
