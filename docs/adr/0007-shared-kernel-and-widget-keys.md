# ADR-0007: shared.kernel для domain-слоёв; ключ виджета как sha256 с глобальным поиском

- Статус: предложено
- Дата: 2026-10-02

## Контекст
**Общие типы в domain.** Модули должны использовать общие доменные типы из `shared`: `TenantId`
(ADR-0006), `DomainError`, `NotFoundError`. По ADR-0001 доступ к модулю — только через `public.py`.
Но `shared/public.py` реэкспортирует и инфраструктуру: `Base`, `TenantRepository` (SQLAlchemy),
`DbSession` (FastAPI). import-linter проверяет и косвенные импорты, поэтому контракт «domain не
зависит от фреймворков, БД и SDK» запрещает любому `*.domain` импортировать `shared.public`.
Это проверено пробным импортом в P1-06a. Модулю `agent` целиком запрещён `fastapi`, так что
с P2 ему тоже будет недоступен `shared.public`. Без решения domain-слои дублируют типы или
работают с голым `UUID` вместо `TenantId`.

**Ключ виджета.** Публичный API (`X-Widget-Key`, docs/contracts.md §1) по ключу определяет
тенанта. Ключ передаётся из браузера, и до его проверки тенант неизвестен. Значит, поиск ключа —
по определению кросс-тенантный запрос. А по ADR-0006 все запросы идут через `TenantRepository`
с явным `tenant_id`. Утечка таблицы ключей не должна позволять выдать себя за виджет тенанта.

## Решение
1. **`app.modules.shared.kernel`** — вторая точка входа модуля `shared`, только для типов без
   зависимостей от фреймворков. Она реэкспортирует `shared.domain`: `TenantId`, `DomainError`,
   `NotFoundError`, `TenantMismatchError`. Её можно импортировать из любого слоя любого модуля,
   включая `domain` и `agent`. `shared/public.py` по-прежнему экспортирует всё, в том числе
   эти типы.
   - В import-linter `kernel` добавлен в `exhaustive_ignores` (как `public`).
   - `kernel` включён в forbidden-контракт «domain и shared.kernel не зависят от фреймворков,
     БД и SDK». Если в kernel попадёт SQLAlchemy или FastAPI, сломается `make check`.
2. **Ключ виджета**:
   - формат `wk_` + `secrets.token_urlsafe(32)` (256 бит энтропии);
   - в БД хранится только `sha256(key)` в hex: `widget_keys.key_hash`, уникальный индекс;
   - открытый ключ показывается один раз при создании (`make seed` печатает его или берёт
     из `SEED_WIDGET_KEY`).
   - Поиск по хэшу без `tenant_id` — отдельный явный сервис (`WidgetKeyResolver`, P1-06b),
     а не метод `TenantRepository`. Это кросс-тенантная операция в смысле ADR-0006: она
     возвращает `TenantId`, и дальше вся работа идёт через репозитории с этим `tenant_id`.
     По тому же принципу сделан `SqlTenantDirectory`: таблица `tenants` сама по себе — список
     тенантов, и `tenant_id` у неё нет.

## Альтернативы
- **Убрать инфраструктуру из `shared/public.py`** (перенести `DbSession` в `app/api`,
  `Base`/`TenantRepository` — в отдельную точку входа). Это решает проблему только частично:
  SQLAlchemy остаётся в `public`, пока там живут репозитории, а их импортируют infrastructure-слои
  всех модулей. Пришлось бы переписать импорты во всех модулях и ввести вторую точку входа
  для инфраструктуры. По сути та же схема с двумя входами, только отделять пришлось бы
  бо́льшую часть.
- **Без общих типов в domain**: порты принимают `UUID`, а приведение к `TenantId` делается
  в application/infrastructure. Код рабочий, но теряется типовая защита ADR-0006 — mypy не
  ловит перепутанные `tenant_id` и `id` как раз в портах, где они чаще всего встречаются.
  Проблема с `agent` при этом не решается.
- **Хранение ключа: bcrypt/argon2 вместо sha256.** Медленные KDF нужны для паролей с низкой
  энтропией. Для случайного токена в 256 бит перебор невозможен и без них. К тому же медленный
  хэш не даёт искать по индексу: пришлось бы хранить отдельный открытый префикс для поиска,
  а на каждый публичный запрос тратилось бы ~50–100 мс CPU.
- **Хранение ключа в открытом виде** (или ключ = идентификатор тенанта). Так проще отлаживать,
  но утечка дампа БД или чтение таблицы через уязвимость сразу дают рабочие ключи всех тенантов.

## Последствия
- domain-слои и модуль `agent` используют `TenantId` и общие ошибки без нарушения границ.
  Правило для новых общих типов: тип без зависимостей кладётся в `shared/domain`
  и реэкспортируется в `kernel`; всё, что тянет фреймворки, — только в `public`.
- ADR-0001 уточняется, а не заменяется: у `shared` две точки входа — `public` (всё) и
  `kernel` (только чистые типы). У остальных модулей точка входа по-прежнему одна.
- ADR-0006 не противоречит: глобальный поиск по ключу — явная кросс-тенантная операция
  в отдельном сервисе. Тест изоляции для `WidgetKeyRepository` остаётся обязательным.
- Потерянный ключ не восстановить: нужно выпустить новый (ротация ключей — вне P1-06,
  нужна к P5-06 / админке). Для локальной разработки — `SEED_WIDGET_KEY` в `.env`.
- Проверку `allowed_origins` по `Origin` нужно добавить в P5-06. Она не заменяет секретность
  ключа: ключ виджета публичен по природе (лежит в HTML сайта), и `allowed_origins` вместе
  с rate limiting (P7-04) — основная защита от его использования с чужих сайтов.
