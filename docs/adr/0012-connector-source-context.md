# ADR-0012: Коннектор получает тенанта и источник; файлы — в `<root>/<tenant_id>/<source_id>/`

- Статус: предложено
- Дата: 2026-10-04

## Контекст
P4-03 вводит коннектор `file` (PDF/DOCX/MD/TXT). Хранилища файлов и API загрузки пока нет.
Интерфейс `SourceConnector` (P4-02a) получал только `Source.config`, то есть коннектор не
знал, чей это источник. Если путь к файлам задаётся в конфиге, изоляцию тенантов не
гарантирует ничто, кроме аккуратности того, кто этот конфиг пишет (админка, P8): ошибка
или подмена `path` открывает файлы другого тенанта, а это нарушает ADR-0006.

## Решение
- Методы `SourceConnector` (`discover`, `fetch`, `changed_since`) принимают
  `SourceSpec(tenant_id, source_id, config)` вместо голого `config`. `run_sync` собирает
  его из `SyncJob`.
- Коннектор `file` читает только каталог `<KNOWLEDGE_FILES_DIR>/<tenant_id>/<source_id>/`.
  Каталог вычисляет коннектор, конфиг на путь не влияет. Симлинки и `..` в `external_id`
  отклоняются, скрытые файлы не читаются.
- Отсутствующий каталог — ошибка синхронизации, а не пустой источник: иначе полный
  discover удалил бы все документы источника.

## Альтернативы
- **Относительный `path` в конфиге под общим корнем.** Интерфейс не меняется, но изоляция
  зависит от корректности конфига. Отклонено.
- **Абстрактное blob-хранилище (S3) сразу.** Пилоту хватает локального диска/тома, а
  раскладка `<tenant_id>/<source_id>/` переносится на префиксы ключей без изменения
  интерфейса коннектора. Отложено до появления загрузки файлов.

## Последствия
- Любой коннектор знает тенанта и источник (для `website` и `http_api` это ещё и
  пригодится в логах и для лимитов на тенанта).
- Загрузка файлов (P8) кладёт их в каталог источника; удаление `Source` должно удалять
  и каталог (пока не реализовано).
- Курсор `file` — максимальный `mtime_ns`. Файл, скопированный с сохранением старого
  mtime, инкрементальная синхронизация не увидит — его подхватит полная.
