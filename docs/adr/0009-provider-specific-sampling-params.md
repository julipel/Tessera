# ADR-0009: Параметры сэмплинга — подсказка, которую применяет адаптер провайдера

- Статус: принято
- Дата: 2026-10-03

## Контекст
ADR-0002 прячет LLM за портом `LLMClient`: провайдеры взаимозаменяемы, и AgentConfig задаёт
`model.primary` и `model.fallback` с разными провайдерами. В контракте `ModelConfig` есть
`temperature` (0–2, по умолчанию 0.3). Это значение идёт по цепочке
`TurnContext.temperature → LLMRequest.temperature → адаптер`.

В P2-07 выяснилось, что параметры сэмплинга больше не общие для провайдеров:
- Anthropic SDK 1.x убрал `temperature`, `top_p` и `top_k` из сигнатуры `messages.create`, потому
  что актуальные модели их не используют. Передать их можно только в обход, через `extra_body`, и
  только для старых моделей. Новые модели такой запрос отклоняют.
- OpenAI Chat Completions `temperature` принимает. Но и там поддержка зависит от модели:
  у reasoning-моделей сэмплинг ограничен. По памяти, это надо сверить через Context7 до P2-08.

Получается, что поддержка сэмплинга — свойство провайдера **и модели**, и со временем оно
меняется. При этом в схеме стоит `default: 0.3`, поэтому temperature есть в каждом конфиге, даже
если тенант её не задавал. Если передавать её «как есть», то сломается первый же запрос
к модели без поддержки сэмплинга. Особенно опасно, что это может быть fallback-модель, которая
включается как раз в момент сбоя основной.

Сейчас адаптер Anthropic (P2-07) молча не передаёт `temperature`. Это решение нужно закрепить
явно, чтобы следующие адаптеры и задача P2-08 вели себя одинаково.

## Решение
1. `LLMRequest.temperature` (и любые будущие параметры сэмплинга) — **необязательная подсказка**,
   а не требование. Адаптер передаёт параметр, только если провайдер его поддерживает, и
   отбрасывает его в остальных случаях. Ошибки при этом нет: ход не должен падать из-за
   параметра качества.
2. Знание о том, что поддерживает провайдер, живёт **только в адаптере** (infrastructure).
   Ни в domain, ни в цикле агента, ни в схеме AgentConfig нет ветвлений по провайдеру.
3. Обходные пути вроде `extra_body` для параметров, убранных из SDK, не используем.
4. В контракте `ModelConfig.temperature` убираем `default: 0.3`. Если поле не задано, у провайдера
   остаётся его собственное значение по умолчанию. В описании поля указываем, что оно применяется
   только там, где провайдер и модель его поддерживают. Схема меняется по ADR-0005, отдельной
   задачей (удобно вместе с P2-08, где ModelConfig впервые доходит до адаптера).
5. Если адаптер отбросил заданный параметр, он пишет это в structlog на уровне debug: видно в
   трейсе, но не шумит.

## Альтернативы
- **Передавать как есть, в том числе через `extra_body`.** Это работает только для старых
  моделей. На актуальных моделях Anthropic запрос падает с 400, а значение по умолчанию 0.3 есть
  в каждом конфиге. Отказались.
- **Реестр возможностей моделей** (таблица «модель → поддерживаемые параметры»). Он точнее, но
  его придётся поддерживать с каждым релизом моделей. Если в таблице окажется ошибка, получим тот
  же 400 или молча потерянный параметр. Сейчас тенантам это не нужно. Можно вернуться к этому
  варианту, когда параметров станет больше, чем temperature.
- **Запрещать temperature в схеме для `provider: anthropic`** (условие `if/then` в JSON Schema).
  Ошибка становится видна при сохранении конфига, но правило нужно повторять для каждого
  провайдера и модели. Схема устаревает при каждом изменении у провайдера, а у OpenAI проблема
  зависит от модели, и схема её не выразит. Отказались.

## Последствия
- ADR-0002 не заменяется, а уточняется: «провайдеры взаимозаменяемы» означает одинаковый порт, а
  не одинаковое поведение каждой настройки. Ни одному принятому ADR это решение не противоречит.
- Одна и та же temperature может работать у primary и не работать у fallback. Эвалы (P3) нужно
  сравнивать с учётом провайдера и модели.
- Каждый новый адаптер в docstring явно перечисляет, какие параметры сэмплинга он передаёт.
  Unit-тест проверяет, что отброшенный параметр не попадает в тело запроса (для Anthropic такой
  тест уже есть).
- Долг:
  - (a) убрать `default: 0.3` и обновить описание поля в `agent_config.schema.json` и
    contracts.md §5, затем `make contracts`;
  - (b) добавить debug-лог об отброшенном параметре в адаптер Anthropic (пока там только
    docstring);
  - (c) проверить поддержку temperature у reasoning-моделей OpenAI и при необходимости научить
    адаптер OpenAI её отбрасывать.
