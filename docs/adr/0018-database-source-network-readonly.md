# ADR-0018: Коннектор `database`: allowlist подсетей, подключение к проверенному IP, read-only

- Статус: принято
- Дата: 2026-10-04

## Контекст
Коннектор `database` (P4-09b) выполняет SQL-запрос из конфига тенанта на сервере из DSN.
Воркер стоит рядом с Postgres платформы, Redis и Qdrant: без ограничений конфиг с хостом
`localhost` и запросом к `widget_keys` вынес бы данные всех тенантов в базу знаний — тот же
SSRF, что у краулера (ADR-0013), только через протокол Postgres. При этом базы клиентов
редко открыты в интернет: пилотная может быть доступна только по приватной сети (VPN,
peering), поэтому «только публичные адреса» недостаточно.

Вторая угроза — запись: запрос из конфига не должен менять данные клиента.

## Решение
- **Адрес.** Коннектор сам резолвит хост из DSN. Разрешено, только если *все* адреса
  публичные (`is_public_address`, ADR-0013) или входят в `SOURCE_DB_ALLOWED_NETWORKS` —
  allowlist CIDR в env платформы, не в конфиге тенанта. Подключение — к проверенному IP:
  DNS rebinding не меняет адрес между проверкой и подключением. Порт — любой.
- **TLS:** `disable | require | verify-ca`, по умолчанию `require`. Подключение идёт по IP,
  поэтому имя хоста в сертификате не сверяется (`verify-full` недоступен); `verify-ca`
  проверяет цепочку до системных CA.
- **DSN** (секрет, ADR-0017) разбирается коннектором; в asyncpg уходят только host, port,
  user, password, database. Параметры DSN запрещены, пароль обязателен: иначе asyncpg взял
  бы `PG*`-переменные и `~/.pgpass` платформы, а параметры стали бы настройками сессии.
  Текст DSN в ошибки не попадает.
- **Read-only:** транзакция `READ ONLY` + `default_transaction_read_only=on` в настройках
  сессии; запрос — подготовленный оператор (несколько команд через `;` невозможны);
  `statement_timeout` и `idle_in_transaction_session_timeout` = `timeout_s`, общий таймаут.
  Рекомендация клиенту — отдельный пользователь только с `SELECT` на нужные объекты.
- **Полнота:** строки читаются курсором; больше `max_rows`, нет колонки маппинга, ошибка
  запроса — ошибка синхронизации (неполный листинг удалил бы сущности, ADR-0012).
- Только PostgreSQL (asyncpg уже в зависимостях). Для mypy — override
  `ignore_missing_imports` для asyncpg (нет `py.typed`).

## Альтернативы
- **Только публичные адреса + флаг «разрешить приватные».** Флаг на проде снимает защиту
  целиком, включая доступ к базе платформы. Отклонено.
- **Проверять адрес и подключаться по имени (`verify-full`).** Полный TLS, но окно для DNS
  rebinding: проверка видит публичный адрес, подключение уходит во внутреннюю сеть.
  Отклонено, как в ADR-0013.
- **Разбирать SQL и пропускать только SELECT.** Ненадёжно (CTE с DELETE, функции с
  побочными эффектами); гарантию даёт READ ONLY транзакция. Отклонено.
- **Egress-прокси / сетевые политики.** Не исключаются как дополнительный рубеж.

## Последствия
- Подключение базы клиента в приватной сети — операция платформы: добавить его подсеть в
  `SOURCE_DB_ALLOWED_NETWORKS`. Подсеть должна быть узкой и не включать инфраструктуру
  платформы — allowlist доверяет всему диапазону.
- Локально и в тестах нужен `["127.0.0.0/8", "::1/128"]`.
- Без проверки имени хоста в сертификате MITM на пути к публичной базе возможен при
  `require`; для публичных баз рекомендуется `verify-ca` с сертификатом публичного CA.
- Другие СУБД — отдельное решение (драйверы — новые зависимости).
