# ADR-0042: Бюджет токенов хода и лимит вывода на шаг

- Статус: принято
- Дата: 2026-10-16

## Контекст
Цикл агента суммирует `usage` по шагам, но не проверяет сумму (REVIEW.md: AG-6).
`LLMRequest.max_output_tokens` цикл не заполняет:
- у Anthropic действует умолчание адаптера (4096);
- у OpenAI (Responses и Chat Completions) вывод ограничен только максимумом модели.

Ход ограничен числом шагов (`max_steps`) и временем (`turn_timeout_s`), но не объёмом. Каждый
шаг заново отправляет всю историю и результаты инструментов, поэтому модель, которая
зациклилась на вызовах с большими результатами, за 6 шагов тратит в разы больше обычного.
Длинный вывод одного шага (повторы, «словесный поток») ничем не ограничен.

Реальный расход: по эвалам (106 ходов, отчёты 2026-10-11) и dev-журналу — медиана около
16 тыс. токенов за ход, p95 около 38 тыс., максимум 45 тыс.; вывод — до 1,5 тыс. за ход.

## Решение
1. **Два поля в `LimitsConfig`** (`packages/contracts/schemas/agent_config.schema.json`).
   Они необязательны, старые конфиги действуют с умолчаниями:
   - `max_output_tokens` — лимит вывода на шаг, по умолчанию 4096, минимум 256. Цикл передаёт
     его в каждый `LLMRequest`. Умолчание не ниже 4096: у reasoning-моделей Responses API в
     лимит входят токены рассуждений, и при малом лимите модель отвечает пусто. Значения
     меньше 4096 схема допускает, но для reasoning-моделей они опасны. Верхней границы в
     схеме нет: максимум у моделей разный, значение выше него провайдер отклонит (400).
   - `max_turn_tokens` — бюджет хода (вход + выход по всем шагам), по умолчанию 120 000,
     минимум 1000. Это около 2,7× от наибольшего хода в эвалах, обычные ходы его не задевают.
2. **Бюджет проверяется после шага, в котором модель просит инструменты.** Если сумма
   превысила `max_turn_tokens`, вызовы этого шага не исполняются и следующего шага нет.
   Ход завершается мягко, как при лимите шагов: `assistant.fallback_message` и
   `TurnCompleted(finish=step_limit)`, лог `agent.turn_budget_exhausted` с `used_tokens` и
   `max_turn_tokens` (уровень warning).
   - Индикаторы вызовов этого шага уже показаны (`ToolStarted` приходит из стрима). Каждый
     закрывается `ToolFinished` с ошибкой «исчерпан бюджет токенов хода», чтобы в журнале
     и SSE не оставалось висячего `tool_started`.
   - Шаг без вызовов — финальный ответ. Он уже показан, и бюджет его не обрезает.
   - Предсказывать расход до шага не пытаемся: оценка токенов по тексту неточна, а
     перерасход на один шаг ограничен `max_output_tokens` и размером контекста.
3. **Отдельной причины завершения в контрактах нет.** Для посетителя бюджет и лимит шагов
   выглядят одинаково (fallback-фраза), поэтому `step_limit` в SSE, HTTP-ответах и истории
   остаётся. Различить их можно по логу. Новое значение потребовало бы изменений в трёх
   схемах и во фронтенде ради одного и того же поведения.
4. **Шаг, остановленный лимитом вывода** (`StopReason.MAX_TOKENS`), остаётся ответом: его
   текст уже у клиента. Цикл пишет предупреждение `agent.output_truncated`.
   - Если шаг при этом пуст (рассуждения съели весь лимит), он не повторяется, как обычный
     пустой ответ: с тем же лимитом повтор тоже был бы пуст. Сразу fallback-фраза,
     `finish=empty_response`; в логе `agent.empty_response` есть `stop_reason`.
   - Вызов инструмента, оборванный лимитом посреди аргументов, получает `arguments=None`.
     Модель видит ошибку разбора, тратится ретрай аргументов, как при любом невалидном вызове.
6. **Передача лимита провайдерам.** Anthropic — `max_tokens`, Responses — `max_output_tokens`,
   Chat Completions (`openai_compatible`) — `max_completion_tokens`. Совместимый API, который
   отклонил `max_completion_tokens` (400 с этим именем в `param` или в тексте ошибки), один
   раз получает повтор со старым `max_tokens`. Модель запоминается до конца жизни процесса,
   лог `llm.legacy_max_tokens`; это тот же приём, что и для temperature (ADR-0009). API,
   который неизвестный параметр молча игнорирует, лимит вывода не соблюдает; бюджет хода
   при этом действует.
5. Сводка истории (`summarizer`) использует свой фиксированный лимит вывода, бюджет хода на
   неё не распространяется: она идёт вне хода, фоновой задачей (P9-01q).

## Последствия
- Расход хода ограничен сверху примерно `max_turn_tokens` + один шаг. Лимит вывода действует
  у Anthropic и OpenAI; у совместимых API — если они понимают `max_completion_tokens` или
  `max_tokens` (п. 6).
- Тенант может поднять бюджет для длинных сценариев или снизить его ради экономии, не меняя
  кода.
- Лимит вывода 4096 ниже максимума некоторых моделей. Если тенанту нужны длинные ответы, он
  поднимает `max_output_tokens`, обрезку видно по логу `agent.output_truncated`.
- `usage` ходов, оборванных ошибкой модели, в бюджет не попадает: такие ходы и так
  завершаются ошибкой.
