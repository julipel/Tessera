# ADR-0026: Слоты хранятся по сценариям; модели — слоты активного, чужой слот — `validation_error`

- Статус: принято
- Дата: 2026-10-07

## Контекст
P6-05. Схема аргументов `update_dialog_state` объединяет слоты всех сценариев (P6-01), а
`DialogState.slots` — плоский словарь. Отсюда две проблемы:
- модель пишет слоты чужого сценария: живой чат — `known_preferences` (слот `gift`) при подборе
  парфюма; эвалы beauty_13 — дубли `for_whom`/`recipient`/`relation`;
- при смене сценария слоты прежнего остаются в состоянии и в Runtime-слое промпта: после
  перехода с крема на подарок модель видит `skin_type`/`concerns` рядом с бюджетом подарка.

Возврат к прежней задаче — обычный ход (beauty_13 ход 3: «а по крему для глаз…»), и тогда
собранное по ней нужно снова. Бюджет одного сценария к другому не относится: бюджет подарка
6000 не должен применяться к крему.

## Решение
1. **Хранение — по сценариям.** `DialogState.slots` — `{ключ сценария: {слот: значение}}`.
   Формат `state_patch` не меняется: плоские `slots` патча пишутся в сценарий патча
   (`active_scenario` патча, если он есть, иначе текущий активный). Без сценария слоты
   не записываются. Слоты неактивных сценариев хранятся и возвращаются в промпт при возврате
   к сценарию.
2. **Модели — только активный сценарий.** Runtime-слой получает плоские `slots` активного
   сценария (`DialogState.prompt_dict()`). Общих слотов нет: общая для сценариев часть —
   `facts`.
3. **Чужой слот — `validation_error`.** JSON Schema `update_dialog_state` остаётся объединением
   слотов всех сценариев: так модель в одном вызове может сменить сценарий и записать слоты
   нового. Обработчик проверяет слоты по сценарию вызова — аргумент `scenario`, без него —
   активный (`ToolContext.active_scenario`); лишние слоты или слоты без сценария отклоняются
   с перечнем допустимых, модель исправляется ретраем.
4. **Активный сценарий — на шаге, а не на начало хода.** Цикл передаёт исполнителю состояние
   после патчей предыдущих шагов: сменённый на шаге 1 сценарий действует для слотов шага 2.
5. Сохранённое до P6-05 плоское состояние читается так: слоты относятся к `active_scenario`,
   без него отбрасываются. Миграция БД не нужна (`Conversation.state` — JSON).

## Альтернативы
- **Схема инструмента по активному сценарию** (инструменты собираются по состоянию). Смена
  сценария и слоты нового в одном вызове не проходят схему; в OpenAI function calling нельзя
  выразить «слоты по значению `scenario`» (`oneOf` на верхнем уровне). Набор инструментов
  пришлось бы пересобирать посреди хода.
- **Перенос при смене сценария только слотов, объявленных в новом.** Переносит бюджет крема
  в подарок (beauty_13), а при возврате к прежнему сценарию его слоты потеряны.
- **Общие слоты** (`shared` в конфиге). Пока не нужны: в demo-beauty общий по имени слот —
  `budget`, но по смыслу он у каждой задачи свой; сведения о клиенте — в `facts`.

## Последствия
- В промпте нет слотов прежнего сценария; при возврате к сценарию его слоты видны со
  следующего хода (в ходе возврата — из истории).
- `ToolContext` знает активный сценарий; `TurnContext.state` в вызове исполнителя — состояние
  на текущем шаге.
- Эвалы (`state_contains`) проверяют слоты активного сценария на конец хода.
- Слоты тенанта без сценариев не пишутся (их и нет в схеме — она строится по сценариям).
